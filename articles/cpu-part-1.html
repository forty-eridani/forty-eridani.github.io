Introduction

Welcome to my new little project after being taking a small hiatus from doing anything on my site. Here, over the course of a few articles (and several months), I will attempt to create an 8 bit CPU and document my experience. This series should not be taken as a proper lesson on how to create a functional CPU. Instead, treat this more as a way to understand the basics and let this hopefully inspire you to learn how to properly design your own CPU. This is just a little project I want to work on since, well, I like computers and would really like to understand them at the most fundamental level. Anywho, enough blabbering, let's get started!

ISA?

"What the hell is an ISA?" I hear you asking. ISA stands for Instruction Set Architecture, and is essentially a description of the interface (the 1s and 0s) you as a programmer use to tell the computer what you want it to do. For most of you, a high level programming language like C provides you an interface to direct the computer, but the processor has no idea to do with the source code, so a compiler takes your source code and turns it into instructions the processor can follow. This likely isn't news to you, but now our job is to write the language for the processor to understand instead of some meager assemblage of flesh. For us, we will be using something called a RISC ISA, or Reduced Instruction Set Computer as opposed to a CISC or Complex Instruction Set Computer. This simply means our ISA description won't be 5,000 pages (I am not joking) and will only contain the essential instructions for making a basic program. We aren't gonna dive into the mathematics of turing completeness or any of the complex math proofs to determine what is able to compute stuff; instead, we will stick to just designing a simple CPU. Our CPU's ISA is going to be quite close to the 6502 since the 6502's ISA is quite simple and clever. To start, let's define our instructions

Making Instructions

The first step to designing a CPU is deciding what we want it to do. Luckily this won't be too complex as our instruction set isn't too large. Because we only have 8 bit registers to play with along with the fact that really don't want instructions to have to take up too many clock cycles, our instruction type will only be 3 bits. That means we can have 8 types of instructions total, which should be plenty. Below is a list of each instruction along with the 3-bit instruction code

  • 000: Arithmetic operations. Stuff like adding, subtracting, shifting, etc
  • 001: Register to Register. This is for transferring data between registers. This could be from general purpose to the stack pointer, stack pointer to general purpose, anything to the accumulator, etc.
  • 010: Register to Memory. This is for loading data from the aforementioned registers to a location in memory.
  • 011: Memory to Register. This instruction is for loading data from memory into a register.
  • 100: Interacting with the Status Register. The status register will be important for storing statuses of stuff that goes on in the ALU, like if the result of a mathematical operation is zero, or if the arithmetic operation needs to carry a bit.
  • 101: Jumping. This instruction is for simply jumping to memory addresses.
  • 110: Branching. This instruction is to change where the program is going based on a status in the status register.
  • 111: The stack. The stack is simply a register that holds memory addresses of an instruction after calling the function, so when a function returns, the memory address of the caller is read from the stack and it can return back to completing stuff after the function call. The stack will take up the first 256 bytes of memory, so our maximum stack depth is 128 (each memory address is 2 bytes).

There we have it. 8 instructions. Some of these will get a little tricky since we only have 5 bits to control what each instruction does specifically, but we can do it. For starters, let's begin designing our first instruction

Arithmetic Operations

Because we used a whole 3 bits to describe the instruction, we are only left with 5 bits to describe how we want to perform the arithmetic operation. 8 arithmetic operations sounds like enough, and that also only takes 3 bits, so let's start with designing that.

Addition and subtraction are of course necessary, so those will be our first instructions. Next up is shifting left and right, and because we want to keep our ALU simple, each of those will only shift once, so they won't require any operand to the accumulator. Next up we should probably include some bitwise operators, so let's include an and, or, xor, and not. There's our 8 instructions, so now we only have 2 more bits to play with. Let's use our first bit to describe whether we want our argument to come from the next address in memory or a register. We don't want to waste a whole bunch of time loading stuff into registers to perform arithmetic operations with a one-off operand. This leaves us with one final bit, which we will use to describe the register. This does mean we only have 2 general purpose registers, but this should be plenty for a simple CPU. Not that we are done with our arithmetic instruction, let's move on to our next instruction

Moving Operations

As with the rest of the instructions, we are left with only 5 bits to decide how we want to move stuff around, but this should be fairly simple given we only have 4 registers that we want to write between: our 2 general purpose registers, the accumulator, and the stack pointer. 4 registers also fit cleanly into 2 bits, so we can fit both our source register and our destination register into this instruction. This leaves us with only a single remaining bit, but we can ignore this we have described everything we need. Next up:

Register to Memory

As always, we have 5 bits to decide what we want to do. Let's use the first 2 bits to describe the register that we want to load to memory. Let's use the next bit to tell us where the source of the address is. If this control bit is zero, then the address is sourced from the next two bytes in memory, but if it is one, then source the address from our two general purpose registers. This probably isn't a super useful feature, but we have extra bits to play with so why not. Now that this is complete, we can move on to our next instruction

Memory to Register

Let's allocate our first 2 bits to determining what register we would like to load from. Our next bit can determine the source of value, whether it comes from the next address in memory if the bit is 0, or from the an address if the bit is 1. The next bit can then control whether the address should be sources from the general purpose registers if 1, or from the next two addresses in memory, if 0. There we have it, a solid load instruction that can direct data where it needs to go. Let's, once again, move on to our next instruction

Status Register Controls

We should probably first figure out what our status register should hold before we start designing the instruction. We want it to hold a carry bit for 16 bit math. We also want it to hold a zero bit that tells us if the last arithmetic operation resulted in a zero (this is useful for branching as you will see later). We should carry a negative bit that tells if the result of the last operation resulted in a negative number. We should also carry an overflow bit that tells if the result of a signed operation is beyond the representable range.
